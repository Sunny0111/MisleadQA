# MisleadQA Candidate Construction Guidelines

Use this guide to construct candidate instances from supplied archived material. It covers SituatedQA, AmbigDocs, and CondAmbigQA. FRED candidates are generated by the deterministic script branch, using archived observations and fixed templates.

## 1 Input and output responsibilities

The caller supplies a bundle with:

- `source` and `upstream_id`;
- the original `upstream_question` and upstream annotations;
- archived entries with `doc_id`, a machine-resolvable `locator`, and original `text` or a textual rendering of the archived structured record;
- a target scope or an explicitly ordered target/alternative pair;
- any allowed donor material for distractors;
- `existing_candidates` and `revision_request` when revising;
- the source-specific generation profile, if required by the build.

Archive identifiers and locators are supplied by the caller. Copy them without inventing file paths, hashes, URLs, or positions. A locator must resolve to the exact archived text being quoted. The archive registry maintained by scripts maps these identifiers to the original records or documents.

Return one candidate object for each proposed fact pair, or a deferred/excluded object explaining why construction is not possible. Return only JSON objects, serialized one per line when multiple records are requested.

The construction model is responsible for identifying a supported pair, writing the question and evidence, marking F replacements, proposing two distractors, and attaching source support. Scripts own final IDs for new candidates, hashes, numerical offsets, canonical normalization, quotas, deduplication, option positions, review metadata, and submission-schema conversion.

## 2 Source boundary

1. Use only the supplied archive. Do not use memory or live web access to provide answers, aliases, conditions, or distractors.
2. Upstream labels and annotations propose candidates; they do not replace source support for the facts.
3. Copy supporting quotations exactly, with their supplied document identifier and locator. Support may be distributed across several quoted spans if their connection is explicit in the archive.
4. Every answer and necessary scope qualifier must be supported. The displayed answer need not be an identical substring when it is an exact, meaning-preserving format conversion; record the original expression and conversion in `notes`. Never add precision or infer an unrecorded qualifier.
5. If required material is missing, return `deferred` and specify what must be archived. The caller obtains supplementary material and submits a new bundle.
6. Label extraction and restatement correctly. Never present generated prose as an original quotation.

Do not run model experiments or use model scores, responses, expected difficulty, or observed effects to propose, orient, or reject candidates.

## 3 Fact-pair requirements

Every candidate consists of two supported facts about the same specific property.

- **Target fact:** the target scope and gold answer.
- **Alternative fact:** the alternative scope and lure answer.

Build only when these requirements hold:

1. Each fact has source support for its subject, queried relation, answer, and necessary qualifiers.
2. The two facts concern the same relation. Release and discontinuation dates are different properties; team and individual scoring records also change the statistical subject.
3. Only one designated scope dimension changes. Other qualifiers needed to interpret the relation remain fixed.
4. Gold and lure are non-equivalent, allowing for supported aliases, formats, units, and precision.
5. Lure is not also valid at the target scope. Different source labels alone do not establish this exclusion: occupations and genres can overlap.
6. Each scope determines one answer at the requested precision. Represent multi-member answers completely and consistently.

Use the target orientation requested by the bundle. If an ordered pair is supplied, its first fact is the target. If neither fixes the orientation, return `deferred` with `needs_orientation`; do not invent an ordering policy or reverse the pair for convenience. Revisions retain the existing orientation unless the request explicitly changes it.

| Dimension value | Change | Source |
|---|---|---|
| `time` | Date or period | SituatedQA |
| `geography` | Location or jurisdiction | SituatedQA |
| `entity` | Identity of a distinct entity sharing an ambiguous name | AmbigDocs |
| `condition` | Explicit qualifying condition on the same relation | CondAmbigQA |

Record the queried property, changed qualifier, and fixed qualifiers in `notes`. Resolve the facts before writing the question.

## 4 Source-specific construction

### 4.1 SituatedQA

Group possible pairs by the same original question.

- For `time`, fix the subject, relation, and relevant location; change the time point.
- For `geography`, fix the relation and any necessary reference time; change the location.

Use archived passages, historical tables, or structured fields that establish the answer at the stated setting. An officeholder source must establish the relevant term. A population source must establish the area, reference date, and statistical definition. Do not rely on a bare annotation answer.

Record provenance separately for G and S:

- `upstream_annotation_reuse`: the setting and answer reuse an upstream annotation and are supported by the archive;
- `document_verified_derivation`: either the setting or answer was added or corrected from archived support.

For a derived side, explain which setting or answer changed and retain the original annotation identifier in `notes`. Deriving one side does not turn the other side into a derived annotation.

Keep the original relation and write the target setting into the question. If a year contains an officeholder transition, use a supported date rather than an ambiguous whole-year reference. Defer unresolved conflicts or statistical-definition changes.

### 4.2 AmbigDocs

Choose two supplied documents describing distinct entities that share the relevant ambiguous name. Different titles alone are insufficient: reject aliases, repeated descriptions, or different names for the same entity. Separate film adaptations can be distinct works.

Both documents must support different answers to the same specific relation. Check that the alternative answer does not also apply to the target entity.

Retain the ambiguous name in the question and add a source-supported distinguishing attribute, such as city, work year, role, or affiliation. The attribute must identify the entity without revealing the answer. City used to identify two same-named buildings is entity disambiguation, not a separate geography manipulation.

For extraction, use contiguous complete sentences or a grammatically complete, self-contained clause containing the answer and entity identifier. Avoid fragments, unresolved pronouns, repeated titles, and missing qualifiers. A faithful restatement is allowed when its source support is retained.

Keep the target identifier in F. S explicitly identifies the other entity. Check that substituting the answer does not create an additional chronology, age, pronoun, or arithmetic contradiction.

### 4.3 CondAmbigQA

Choose two conditions within the same upstream question. In `notes`, identify the subject, exact relation, changed condition, fixed qualifiers, and supporting spans.

Release format or performance mode can qualify when they change the condition on the same subject and property. A statistical unit or event stage does not automatically qualify: changing the statistical subject or the queried relation is inadmissible. Approval, enactment, and first availability are distinct properties.

The archive must support the answer under the stated condition. It need not explain a causal mechanism. Bare answers or condition labels are insufficient.

For film releases, fix the film and documented market. Do not infer a country from a website domain or familiar date. If the archive instead identifies one particular announced release schedule, explicitly fix that same schedule in the question and G/F/S. Do not add a country that the archive does not establish. Defer if neither a common market nor an unambiguous common schedule is supported.

Reject pairs that change several qualifiers at once, have overlapping conditions allowing multiple answers, treat different laws/events as one, or substitute participants for performers. Preserve uncertainty and temporal precision, including the distinction between “by” and “on” a date.

Supplementary contexts must already be archived and linked to this upstream question.

## 5 Question and answers

Write generated questions, answers, and G/F/S evidence in English. Preserve source-backed spellings of personal and place names, including Latin letters and diacritics. For non-English sources, keep supporting quotations in the original language and write the restated evidence in English; use `faithful_source_restatement` for translated evidence. Preserve the original upstream wording in `base_question` and the original text in the input archive.

1. Copy the original question to `base_question`.
2. Write `question` with the supported target entity, relation, and required scope. Do not disclose gold or lure.
3. Set `gold_answer` from the target fact and `lure_answer` from the alternative fact.
4. Preserve units and requested precision. Do not round values, expand abbreviations without support, treat version identifiers as decimals, or convert a year/month into a full date.
5. Add only archive-supported aliases. Keep literal source expressions in supporting quotations. Scripts may derive deterministic formatting variants; the model must not invent semantic aliases.

Partial names and parts of dates are not automatically aliases of the complete answer. Keep such possible leakage forms distinct from scoring aliases in `notes` when relevant.

## 6 G F and S

| Variant | Scope | Answer | Intended factuality | Intended applicability |
|---|---|---|---|---|
| G `correct` | Target | Gold | True | True |
| F `false` | Target | Lure | False | True |
| S `mis_scoped` | Alternative | Lure | True | False |

These are construction intentions, not review certifications. Scripts add the corresponding labels to the projected evidence records.

### 6.1 Construct G and S

G states the target subject, relation, scope, and gold. S states the alternative subject or scope, the same relation, and lure. Both are supported by their own source references.

Use `contiguous_source_prose` when both are exact source excerpts. Use `faithful_source_restatement` when source-supported rewriting is needed, retaining exact supporting quotations separately.

S must express the alternative scope in its own text. A reader must not need a hidden document title or metadata. It must provide the queried property; omitting the property creates missing information rather than scope inapplicability.

Preserve qualifications, uncertainty, units, and precision. Do not turn a date upper bound into an exact occurrence date or an estimate into a census count. Keep both texts concise and comparable in style without adding unsupported background.

**Answer isolation.** G must contain gold without lure expressions; F and S must contain lure without gold expressions. Apply this restriction to rendered evidence using discriminating answer aliases. Shared name or date components alone are not leakage. Supporting quotations may contain both facts.

Numerical length, ratio, and overlap thresholds are defined in `selection_and_balancing.md` and supplied through the generation profile when needed. Do not invent missing thresholds. Their scripted enforcement is not part of this model's output.

### 6.2 Derive F

F is G with registered answer expressions replaced by lure. Leave every other character unchanged.

For each replacement, output:

- `before`: the exact expression in the final G;
- `after`: the appropriate lure expression;
- `occurrence`: a one-based occurrence number for that exact `before` string in G.

Occurrences are counted case-sensitively, left to right, as non-overlapping exact substring matches in the **original final G**, not the progressively edited text. The same `(before, occurrence)` cannot be registered twice; selected spans cannot overlap. Scripts resolve these markers to zero-based Unicode code-point `start`/`end` offsets with an exclusive end and apply replacements from right to left.

Register every expression asserting the target gold answer, including supported aliases where necessary. Do not replace unrelated same-year numbers, another person's surname, or another event's answer merely because a string matches.

Write the resulting F text and the replacement markers. F must remain fluent, preserve the target scope, contain no residual target-gold assertion, and create no independent contradiction beyond the intended false answer. If this cannot be achieved, reconstruct source-supported G/S and derive F again, or defer. Never freely rewrite F.

F's `source_refs` is `[]`: G's source is not evidence that F is true.

## 7 Propose two distractors

Propose `distractor_1` and `distractor_2`, without option letters. Each must:

- represent the same queried relation under a supported scope;
- be wrong at the target scope;
- be non-equivalent to gold, lure, and the other distractor;
- match answer type, unit, precision, and display format;
- introduce no unintended answer support or detectable distractor expression in the question or G/F/S.

| Source | Allowed pool |
|---|---|
| SituatedQA | Other archived settings of the same question; supplied cross-question donor facts only when the specific relation matches |
| AmbigDocs | Other entities with the same ambiguous name and relation; supplied relation-matched donor facts as a fallback |
| CondAmbigQA | Archived property/context facts for the same upstream question only |

Attach supporting quotations for both the value and scope. A bare upstream answer label is insufficient. For a cross-question donor, record its upstream ID, subject, scope, and relation-match explanation. Only use donors included in the bundle; do not search unrelated questions yourself.

If only zero or one admissible distractor exists, return `deferred` with `insufficient_distractors`. Preserve the partial finding in the explanation; do not fabricate choices.

## 8 Candidate output

This is an **intermediate construction interface**, not the submission schema. The template below defines the shape; actual outputs must contain supported values and supplied source locators.

```json
{
  "decision": "candidate",
  "candidate_id": null,
  "source": "SituatedQA",
  "dimension": "geography",
  "upstream_id": "<supplied upstream identifier>",
  "base_question": "<original question>",
  "question": "<target question>",
  "property": "<specific queried relation>",
  "target_scope": [{"name": "<qualifier>", "value": "<value>"}],
  "alternate_scope": [{"name": "<qualifier>", "value": "<value>"}],
  "gold_answer": "<gold>",
  "lure_answer": "<lure>",
  "gold_aliases": [],
  "lure_aliases": [],
  "evidence_style": "faithful_source_restatement",
  "evidence": {
    "correct": {
      "text": "<G>",
      "source_refs": [{"doc_id": "<supplied ID>", "locator": "<supplied locator>", "quote": "<exact archive span>"}],
      "provenance": "upstream_annotation_reuse"
    },
    "false": {"text": "<F>", "source_refs": []},
    "mis_scoped": {
      "text": "<S>",
      "source_refs": [{"doc_id": "<supplied ID>", "locator": "<supplied locator>", "quote": "<exact archive span>"}],
      "provenance": "upstream_annotation_reuse"
    }
  },
  "false_edits": [{"before": "<exact expression in G>", "after": "<lure expression>", "occurrence": 1}],
  "distractors": [
    {
      "id": "distractor_1",
      "value": "<answer>",
      "scope": [{"name": "<qualifier>", "value": "<value>"}],
      "source_refs": [{"doc_id": "<supplied ID>", "locator": "<supplied locator>", "quote": "<exact archive span>"}],
      "donor_upstream_id": null
    },
    {
      "id": "distractor_2",
      "value": "<answer>",
      "scope": [{"name": "<qualifier>", "value": "<value>"}],
      "source_refs": [{"doc_id": "<supplied ID>", "locator": "<supplied locator>", "quote": "<exact archive span>"}],
      "donor_upstream_id": null
    }
  ],
  "notes": "<changed qualifier; fixed qualifiers; alias/format support; derivations or donor relation matches>"
}
```

Rules for this interface:

- New proposals use `candidate_id: null`; scripts assign stable IDs. Revisions copy the supplied existing ID.
- Scope names are explicit and unique within each scope. Values are strings. Scripts convert this working representation to the typed submission scope representation.
- A source `locator` is copied in its supplied type, including an object if the archive uses structured locators. The string in the template is not a requirement to flatten it.
- Include all spans needed to support the facts and any aliases. The source references shown as single entries may contain several entries.
- SituatedQA provenance uses the two values in Section 4.1. For AmbigDocs use `archived_document`; for CondAmbigQA use `archived_context` or `archived_supplement` as appropriate. Identify mixtures in `notes`.
- Include exactly the two distractor identities. `donor_upstream_id` is null for same-question material and the supplied donor identifier for a cross-question fallback.
- Do not include option labels, answer keys, model-generated F edit offsets, group IDs, review fields, or evaluation eligibility. Preserve numerical coordinates and hashes already present in supplied source locators.

Current builders consume source-specific plans rather than this intermediate object. The scripted handoff must resolve supplied archive references, convert occurrence markers to F edit offsets, and map candidate fields into the corresponding plan format before running the existing pipeline.

For unsuccessful construction, return:

```json
{
  "decision": "deferred",
  "candidate_id": null,
  "source": "CondAmbigQA",
  "upstream_id": "<supplied upstream identifier>",
  "reason": "insufficient_distractors",
  "explanation": "<what was supported, what is missing, and what additional archived material is needed>"
}
```

For deferred or excluded revisions of an existing candidate, retain its supplied `candidate_id`. Use `null` for unsuccessful new proposals.

Use `deferred` for missing support or an unresolved decision; use `excluded` for an established violation. Reason codes include `needs_source`, `needs_orientation`, `source_conflict`, `different_property`, `multiple_dimensions_changed`, `lure_valid_at_target`, `non_unique_answer`, `unclean_substitution`, `insufficient_distractors`, and `market_unresolved`. Use `other` only with a precise explanation.

Known overlap with an existing candidate may be flagged in `notes`; final duplicate removal belongs to scripts.

## 9 Revisions

When revising the same fact pair, retain the supplied ID, address the request, and rebuild dependent content. Changing G requires regenerating F and its markers; changing an answer or scope requires reconsidering both distractors and the question. An instruction to fix one issue does not permit leaving a newly introduced inconsistency.

If repair requires a different fact pair, return a new proposal with `candidate_id: null`, identify the old ID in `notes`, and explain that replacement is proposed. Do not automatically mark the old record excluded unless its violation is established; scripts and review stages decide membership.

Before returning a candidate, confirm that the source support is attached, the pair meets the same-property and scope requirements, the question is unambiguous, F is a clean substitution, S explicitly gives the alternative scope and property, the evidence variants satisfy answer isolation, and both distractors are supported and distinct.

## 10 Illustrative example

This example illustrates the format only. It is not a dataset instance. Document IDs, locators, and quotations below are placeholders; in real output, every value must come from the supplied archive.

**Input (abridged).** A SituatedQA bundle for the upstream question "Who was the reigning monarch?" with an ordered geography pair: target Norway 1931, alternative Sweden 1931. Assume the upstream annotations for this question include Norway/1931 → Haakon VII and Sweden/1931 → Gustaf V, and that archived passages support each of them. The archive also contains supported passages for Denmark and Belgium in 1931 under the same upstream question.

**Fact pair.** The year is fixed at 1931 and the property is "reigning monarch"; only the country changes.

| Evidence | Text |
|---|---|
| G | In 1931, the king of Norway was Haakon VII. |
| F | In 1931, the king of Norway was Gustaf V. |
| S | In 1931, the king of Sweden was Gustaf V. |

- G contains gold (Haakon VII) and no lure; F and S contain the lure (Gustaf V) and no gold.
- F differs from G only in the registered answer span.
- S states Sweden in its own text and gives the same property.

**Output.**

```json
{
  "decision": "candidate",
  "candidate_id": null,
  "source": "SituatedQA",
  "dimension": "geography",
  "upstream_id": "<supplied upstream identifier>",

  "question": "Who was the king of Norway in 1931?",
  "property": "reigning monarch",
  "target_scope": [{"name": "country", "value": "Norway"}, {"name": "year", "value": "1931"}],
  "alternate_scope": [{"name": "country", "value": "Sweden"}, {"name": "year", "value": "1931"}],
  "gold_answer": "Haakon VII",
  "lure_answer": "Gustaf V",
  "gold_aliases": [],
  "lure_aliases": [],
  "evidence_style": "faithful_source_restatement",
  "evidence": {
    "correct": {
      "text": "In 1931, the king of Norway was Haakon VII.",
      "source_refs": [{"doc_id": "doc_no", "locator": {"start": 0, "end": 120}, "quote": "<exact archive span establishing Haakon VII's reign over Norway in 1931>"}],

    },
    "false": {
      "text": "In 1931, the king of Norway was Gustaf V.",

    {
      "id": "distractor_1",
      "value": "Christian X",
      "scope": [{"name": "country", "value": "Denmark"}, {"name": "year", "value": "1931"}],

```

The locator objects stand for whatever the caller supplies and are copied unchanged. Under evidence-only reading, G supports the gold answer, F supports the lure, and S gives no answer for Norway.
