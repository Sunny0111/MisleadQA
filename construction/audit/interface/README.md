# MisleadQA local review app

React + Vite with a small Node HTTP server. Six reviewers (A1–A6), 50 items
each, one stage, Q1–Q3 beside G/S/F. Uses local JSON files. No database,
Docker, access codes, external fonts, or remote services are required.

## Run locally

Use Node.js **24.14 or later**. From this directory:

```powershell
npm install
npm run freeze
npm run build
npm start
```

Open **http://127.0.0.1:3001**. Keep the terminal running while reviewing;
Ctrl+C stops the server. Once installed and built, only `npm start` is needed.
Type your assigned reviewer ID (A1–A6), then click **Open my assignment** or
press Enter. Lowercase letters and surrounding spaces are accepted. There is
no reviewer picker or public progress list. **Exit review** clears the ID field.
If the system Node is older, install a supported version and ensure `node`
and `npm` are available on `PATH` before starting.

The same files work on another computer with Node 24. Keep the repository
layout, especially `../frozen/main150-v1`, intact. Copy the same freeze to all
six reviewers; never generate a different sample for each reviewer.

## Files saved on this computer

Default directory, relative to the repository:

```text
construction/audit/responses/main150-v1/
  A1.draft.json
  A1.submitted.json
  ...
  A6.draft.json
  A6.submitted.json
```

Files are created only after actual edits or submissions. The final file
contains all 50 judgments, notes, per-item update times, reviewer ID, displayed
question/options/passages/answers/scopes, sample and assignment hashes,
submission time, and a SHA-256 receipt. The hash covers JSON.stringify of the
final object without its `sha256` property, in its stored property order.

Draft writes are serialized and atomically replace a JSON file. Revision
checks reject stale edits from another tab. A browser recovery copy retains
pending writes if a connection fails; it is not the official saved record.
Final files are published exclusively and cannot be overwritten by the app.
Submission retries return the existing receipt. Keep regular copies of the
response folder after reviewers finish.

To choose a different local output folder, set `REVIEW_DATA_DIR` before
starting. Relative paths are resolved from the current working directory.
The app adds `main150-v1` under it:

```powershell
$env:REVIEW_DATA_DIR = '.\reviews'
npm start
```

Only one running server should use a response folder. The service binds to
127.0.0.1 and accepts local browser origins. Manually entered reviewer IDs
identify assignments; they are **not passwords or identity verification**.
Typing another valid ID still opens that assignment. Manual entry reduces
accidental switching but does not provide access control. Use this on trusted
local computers. The reviewer list and progress-list endpoint are removed;
someone with local file access can still read the response files. This is not a public server.
For separate computers, collect the six submitted files manually; there is
no remote synchronization.

If saving fails, the interface shows an error instead of “Saved locally.”
Keep the page open, retry, or download the recovery copy. A conflict from a
second tab requires downloading a recovery copy before reloading. For a
submitted correction, keep the original final file and record an organizer
amendment separately rather than deleting the lock.

## Development and verification

```powershell
npm test
```

Tests verify frozen-source integrity, quotas, allocation, JSON persistence,
restarts, stale revisions, immutable submissions, HTTP validation, and lost
response recovery. All test responses use synthetic items in temporary
directories; formal human audit files are never generated by tests.

For an isolated manual UI submission check, run `node tests/ui-smoke.js` and
open http://127.0.0.1:3002. It uses clearly synthetic items in a temporary
folder, with 49 test items pre-filled for A1 so the final-item validation and
submit flow can be checked quickly. It never loads the real sample. Stop it
after testing; do not distribute its output as human review records.

For development, run `npm run server:dev` and `npm run dev` in two terminals.
Vite at http://127.0.0.1:5173 proxies `/api` to port 3001. The production local
server serves the built `dist` files and the same API on port 3001.

The completed audit's collected A1–A6 submissions are in
`construction/human audit/main150-v1/`. The app's default response directory
remains a local working directory. See the [organizer protocol](../README.md)
for the current sample, completed results, analysis command, and adjudication rules.
